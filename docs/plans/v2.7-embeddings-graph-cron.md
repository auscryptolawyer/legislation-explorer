# v2.7 — Vector Embeddings, Graph, & Monthly Cron

> **For Hermes:** Use subagent-driven-development to implement this plan task-by-task. Each task is 2-10 minutes of focused work.

**Goal:** Replace FTS5 search with OpenAI-powered vector search, embed all content types (sections, cases, rulings, commentary), update the graph to use similarity-based proximity, and standardise monthly ingestion scripts.

**Architecture:**
- **Model:** OpenAI text-embedding-3-small (1536-dim, $0.02/1M tokens). Running on existing server with `openai` package.
- **Storage:** Same `embeddings.db` SQLite schema — just widen `embedding` BLOB from 384×4=1536 bytes to 1536×4=6144 bytes. Add `model` column for provenance.
- **Cost estimate:** ~50M tokens total = **~$1.00** (22K existing re-embed + 12K rulings @2.5K tokens + 7K cases @150 tokens)
- **Graph:** Precomputed k-NN similarity index (top-20 per node) → force-directed layout with weighted edges. Hard edges (cross-refs) remain as overlay.
- **Search UI:** Move from FTS5-hybrid to vector-first with type filters. Keep FTS5 as fallback for exact phrase matches.

**Tech Stack:** OpenAI API, sentence-transformers (removed in favour of `openai`), FastAPI, React, SQLite, D3.js force layout

### Part C: Graph Update — Similarity Proximity (~20 min)

#### Task C1: Build k-NN similarity index

**Objective:** Precompute top-20 nearest neighbours per embedding node using cosine similarity. Store in `embeddings.db` as a `similarity_index` table.

**Files:**
- Create: `scripts/build_similarity_index.py`
- Modify: `data/embeddings.db` (new table)

**Schema:**
```sql
CREATE TABLE similarity_index (
    embedding_id INTEGER NOT NULL REFERENCES embeddings(id) ON DELETE CASCADE,
    neighbor_id INTEGER NOT NULL REFERENCES embeddings(id) ON DELETE CASCADE,
    similarity REAL NOT NULL,
    PRIMARY KEY (embedding_id, neighbor_id)
);
```

**Script:**
```python
#!/usr/bin/env python3
"""Build k-NN similarity index from embeddings.db.

For each embedding node, find the top-20 most similar nodes.
Uses numpy dot product (cosine similarity of L2-normalised vectors).
Skips self-similarity. Only computes for items that have at least
10 neighbours above similarity threshold 0.4.
"""

import sqlite3, numpy as np
from pathlib import Path

DB = Path("data/embeddings.db")
K = 20
THRESHOLD = 0.4

# Read all embeddings
conn = sqlite3.connect(str(DB))
rows = conn.execute("SELECT id, embedding FROM embeddings").fetchall()
ids = np.array([r[0] for r in rows])
vectors = np.frombuffer(b"".join(r[1] for r in rows), dtype=np.float32).reshape(len(rows), -1)
vectors = vectors / np.linalg.norm(vectors, axis=1, keepdims=True)  # L2 normalise

# Batch compute similarity
sim = vectors @ vectors.T  # (N, N) matrix

# For each node, find top-K neighbours
conn.execute("DELETE FROM similarity_index")
conn.execute("BEGIN")
for i in range(len(ids)):
    # Get top-K indices (excluding self)
    order = np.argsort(-sim[i])  # descending
    order = order[order != i][:K]  # exclude self, take top K
    for j in order:
        if sim[i, j] >= THRESHOLD:
            conn.execute(
                "INSERT INTO similarity_index VALUES (?, ?, ?)",
                (int(ids[i]), int(ids[j]), float(sim[i, j]))
            )
conn.commit()
conn.close()
```

**Performance:** 41K items → matrix multiply of (41K × 1536) × (1536 × 41K) = ~1.7B flops. On CPU numpy (MKL/openblas) ~2-3 min. On GPU virtually instant but not needed.

Expected: 500K-800K rows

2. Query `similarity_index` for top-20 neighbours
